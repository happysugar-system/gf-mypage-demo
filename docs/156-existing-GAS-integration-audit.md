## 統合に必要な修正
1. 既存156を唯一の本番同期エントリポイントとする。今回追加した GF_連絡先変更_自動同期 は重複実行させない。
2. 承認はSupabaseの自動承認トリガーのまま。管理者による都度の手動承認は不要。
3. GASからservice_roleを直接使う設計は避け、サーバー側で本人照合済みのキューAPIと完了記録APIに寄せる。ただし現行キューAPIには156が行う氏名照合がないため、同等の検証を移植してから本番有効化する。
4. 156が依存する「対象スプレッドシートを開く_」の存在と、既存時間トリガーの呼び出し元を確認する。
5. 書き込み有効化はGAS本体への反映と統合検証後。現状は本番未デプロイ・書き込み停止のまま。
6. スプシ更新とSupabase完了記録間の通信障害に備え、再試行時に同じ値なら安全に完了記録できる設計を維持。
7. 130〜134、157、既存同期の動作を変更しない。
