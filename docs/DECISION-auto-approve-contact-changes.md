# GOLD FIRST ドライバーマイページ — 連絡先変更の確定仕様（ユーザー決定）
更新: 2026-11-13

## 最優先・変更禁止の要件
**連絡先変更は自動承認。管理者による都度の手動承認を設けない。**
この自動承認はユーザーが意図的に選択した要件。LINE連携、電話番号、本人確認、既存アカウントとの紐付けを準備しているのは、手動確認なしで安全に自動処理するためである。
AI/開発者は「安全のため」と称して自動承認を勝手に停止したり、管理者承認に置き換えてはならない。変更提案が必要なら事前にユーザーへ確認すること。

## 期待する動作
1. 本人確認済みのドライバーがマイページでログインする。
2. 電話番号またはメールアドレスの変更を申請する。
3. サーバー側でログイン認証・登録承認済み・auth_user_idとDriverIDの一意な紐付けを検証する。
4. 条件を満たす申請は**自動承認**する（管理者操作なし）。
5. 承認済み申請をGASが取得し、ドライバーマスターの該当DriverIDの電話番号・契約者メールアドレスのみ更新する。
6. Supabaseに同期結果を記録し、同じ申請の重複反映を防止する。失敗時は再試行可能にする。

## セキュリティ要件（自動承認を妨げない）
- 自動承認の判定はサーバー側。申請者が他人のDriverIDを指定して更新できないようにする。
- メール変更に伴うログイン認証先の更新は、既存の申請承認と別の安全な認証フローで処理する。必要なら新メールへの確認コード等を自動で送る。
- 電話番号・LINE認証の既存の設計を活かす。ユーザーに毎回管理者承認を求める設計にはしない。
- 認証トークン、service_role、個人情報を公開コードやログに書かない。
- 本番実データを不用意に書き換えない。テスト用GASは最終的に削除できるようにする。
