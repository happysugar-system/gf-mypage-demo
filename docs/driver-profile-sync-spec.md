# ドライバー初回登録・連絡先変更と台帳同期（実装仕様）

## 対象
既存DriverIDを正本として、LINE本人連携・初回プロフィール入力・登録後の電話番号変更を行う。生年月日は収集しない。

## 本人入力項目
氏名、フリガナ、電話番号、契約者メールアドレス、所属会社名、稼働エリア、紹介元、緊急連絡先氏名、緊急連絡先電話番号、緊急連絡先メールアドレス。
DriverID、登録日、ステータス、備考、免許証フォルダ、割当VehicleID、割当車番は本人編集不可。

## 初回LINE連携
LINE IDトークンをサーバーで検証し、既存マスターの氏名・電話番号と照合。複数候補・不一致・既連携は自動確定せず、詳細を漏らさずエラー表示。氏名と電話番号だけで個人情報閲覧を解放しない。登録済み電話番号へのSMS等の所有確認を行う。本人申告の所属会社で閲覧権限を付与しない。

## 更新処理
- 既存のgf_mypage_contact_change_requestsを活用する。現在はpending/approved/rejectedの申請方式であり、登録だけでマスターが更新されるわけではない。
- 電話番号変更は新番号の所有確認後、サーバー側でDriverIDとLINE連携の所有者を検証して更新。
- Supabaseの正本更新とスプレッドシートの同じDriverIDの行への同期は、再試行可能なジョブと同期状態で管理。部分失敗時は成功と表示しない。
- 変更履歴に変更前・変更後・日時・実行主体・同期状態を保存する（個人情報へのアクセス制限を実装）。
- スプシの行番号ではなくDriverIDで照合。重複・不一致時は更新停止。氏名等の既存値は初回補完で無条件上書きしない。
- 他社情報を参照できないRLSと会社別認可を適用。
